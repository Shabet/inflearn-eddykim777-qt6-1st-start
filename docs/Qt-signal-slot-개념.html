Qt signal slot 개념

Qt 6 시그널/슬롯을 처음 접하는 사람이, 문법부터 내부 구현·디자인 패턴까지 한 흐름으로 이해하도록 정리한 문서입니다. 실습 코드는 section03/P01_SignalSlot 입니다. 

connect(ui->hSlider, &QSlider::valueChanged, this, &Widget::slot_valueChanged);
connect(this, &Widget::sig_textChanged, this, &Widget::slot_textChanged);

1. 이 문서에서 다루는 것

시그널/슬롯은 “어떤 일이 생기면, 미리 연결해 둔 함수를 호출한다”는 개념입니다. 버튼 클릭, 슬라이더 값 변경처럼 언제 일어날지 모르는 사건에 잘 맞습니다.

단계내용
사용connect, emit, 생성자, UI 폼
규칙인자 호환, private / slots:, this
빌드moc, .o, 실행 파일, “기계어” 용어
비교일반 콜백, 스레드, 원격
내부QMetaObject, Connection, activate
패턴Observer, Command, Adapter, Strategy

Qt 6.5 이상, 함수 포인터 connect(Qt 5에서 도입, Qt 6 권장 문법)를 기준으로 합니다.

2. 실습 예제 전체 소스

2.1 widget.h

Q_OBJECT가 있어야 moc가 이 클래스를 처리합니다. Ui::Widget은 지금 작성 중인 Widget이 아니라 widget.ui에서 생성되는 폼 클래스입니다. 

#ifndef WIDGET_H
#define WIDGET_H

#include <QWidget>

QT_BEGIN_NAMESPACE
namespace Ui {
class Widget;
}
QT_END_NAMESPACE

class Widget : public QWidget
{
    Q_OBJECT

public:
    explicit Widget(QWidget *parent = nullptr);
    ~Widget() override;

private:
    Ui::Widget *ui;

signals:
    void sig_textChanged(QString str);

private slots:
    void slot_valueChanged(int val);
    void slot_textChanged(QString str);
};
#endif // WIDGET_H

2.2 widget.cpp

#include "widget.h"
#include "ui_widget.h"

Widget::Widget(QWidget *parent)
    : QWidget(parent)
    , ui(new Ui::Widget)
{
    ui->setupUi(this);

    connect(ui->hSlider, &QSlider::valueChanged, this, &Widget::slot_valueChanged);
    connect(this, &Widget::sig_textChanged, this, &Widget::slot_textChanged);
}

Widget::~Widget()
{
    delete ui;
}

void Widget::slot_valueChanged(int val)
{
    QString str = QString("%1").arg(val);
    ui->leText->setText(str);

    emit sig_textChanged(str);
}

void Widget::slot_textChanged(QString str)
{
    ui->leTextCopy->setText(str);
}

3. 프로그램이 하는 일

사용자가 가로 슬라이더를 움직임 → QSlider가 내부에서 emit valueChanged(새 값) → Widget::slot_valueChanged(int val) leText에 숫자 문자열 표시 emit sig_textChanged(str) → Widget::slot_textChanged(QString str) leTextCopy에 같은 문자열 표시

시그널이 두 단입니다.

  1. Qt가 제공하는 QSlider::valueChanged(int) — 직접 emit하지 않음
  2. 직접 선언한 Widget::sig_textChanged(QString) — 슬롯 안에서 emit

emit는 빈 매크로입니다. 컴파일러에게는 sig_textChanged(str);과 같습니다. 읽는 사람에게 “이 호출은 시그널이다”라고 알려 줄 뿐입니다.

4. connect 네 인자와 this

connect(ui->hSlider, &QSlider::valueChanged, this, &Widget::slot_valueChanged);
인자값의미
1ui->hSlider시그널을 보내는 객체
2&QSlider::valueChanged그 객체의 시그널 (클래스 멤버 함수 주소)
3this슬롯을 받을 객체
4&Widget::slot_valueChanged그 객체의 멤버 함수

생성자 Widget::Widget 안의 this는 지금 만들고 있는 Widget 인스턴스입니다. 타입이 Widget*입니다. Widget은 클래스 이름이고, this는 그 클래스의 현재 객체입니다. 창이 두 개면 this가 서로 다릅니다.

Widget A → A의 슬라이더 → A.slot_valueChanged() Widget B → B의 슬라이더 → B.slot_valueChanged()

&Widget::slot_valueChanged만으로는 “함수 종류”만 알고, 어느 인스턴스에서 실행할지는 this가 정합니다. 비정적 멤버 함수 주소는 반드시 &클래스::함수 형식입니다.

5. SIGNAL() / SLOT() 없이 연결하기

예전 매크로 방식:

connect(ui->hSlider, SIGNAL(valueChanged(int)), this, SLOT(slot_valueChanged(int)));

권장하는 함수 포인터 방식:

connect(ui->hSlider, &QSlider::valueChanged, this, &Widget::slot_valueChanged);
매크로 방식함수 포인터 방식
SIGNAL(valueChanged(int))&QSlider::valueChanged
SLOT(slot_valueChanged(int))&Widget::slot_valueChanged

인자 타입 (int)는 쓰지 않습니다. 함수의 주소만 넘깁니다.

  • 이름이나 타입이 틀리면 컴파일 에러입니다. 매크로는 문자열이라 실행 전까지 모를 수 있습니다.
  • 오버로드가 하나뿐이면 위처럼 바로 씁니다. QSlider::valueChanged는 int 하나라 문제 없습니다.
#define SIGNAL(a)  "2"#a     // "2valueChanged(int)"
#define SLOT(a)    "1"#a     // "1slot_valueChanged(int)"

6. private 과 slots: 의 의미

private slots:
    void slot_valueChanged(int val);
키워드하는 일
privateC++ 접근 제한. 밖에서는 호출/주소 획득 불가
slots:moc가 메타오브젝트에 등록. 예전 SLOT() 문자열 조회용

private이 의미 없는 것이 아닙니다. C++ 접근 제한은 그대로입니다.

생성자 안에서는 this의 private 멤버에 접근할 수 있으므로 연결됩니다. 클래스 밖에서 &Widget::slot_valueChanged를 쓰면 컴파일 에러입니다.

함수 포인터 connect는 C++ 함수 주소를 쓰므로 slots: 없이 일반 멤버 함수여도 됩니다.

private:
    void slot_valueChanged(int val);  // slots: 없음

예전 매크로는 문자열로 슬롯을 찾아 moc를 타기 때문에, 밖에서도 private 슬롯에 연결할 수 있었습니다. private slots:의 원래 의도는 “C++에서는 직접 호출하지 못하게 하고, Qt connect로는 연결할 수 있게 한다”는 것이었습니다. 새 문법에서는 그 우회가 없습니다. 밖에서 연결되게 하려면 함수를 public으로 두면 됩니다.

7. 생성자 초기화 목록

Widget::Widget(QWidget *parent)
    : QWidget(parent)
    , ui(new Ui::Widget)
{
    ui->setupUi(this);
    connect(...);
}

콜론(:) 뒤는 멤버 초기화 목록입니다. 생성자 본문보다 먼저 실행됩니다.

: QWidget(parent)

Widget은 QWidget을 상속합니다. 기반 클래스 생성자는 초기화 목록에서만 호출할 수 있습니다. parent는 Qt 위젯 부모입니다. main에서 Widget w;처럼 최상위 창이면 nullptr입니다.

, ui(new Ui::Widget)

widget.ui를 uic가 바꾼 폼 객체를 new로 만듭니다. ui->hSlider처럼 쓰게 하고, 소멸자 delete ui;와 짝입니다.

1. QWidget(parent) Qt 위젯으로서의 기본 준비 2. ui(new Ui::Widget) UI 폼 객체 생성 3. setupUi(this) 실제 컨트롤을 이 창에 배치 4. connect(...) 시그널/슬롯 예약 (아직 호출하지 않음)

8. 소스에 없는 valueChanged는 언제 호출되나

&QSlider::valueChanged는 프로젝트 소스에 없습니다. Qt 라이브러리 QSlider가 미리 만들어 둔 시그널입니다. connect는 지금 호출하지 않고, “값이 바뀌면 슬롯을 실행해라”는 예약만 합니다.

마우스 드래그, 키보드, setValue()로 값이 바뀌면 Qt 내부에서 emit valueChanged(새 값)이 나갑니다.

시그널누가 emit 하나
QSlider::valueChangedQt (QSlider 구현)
Widget::sig_textChanged우리 코드 (slot_valueChanged 안)

9. 시그널과 슬롯의 인자 규칙

이 예제는 인자 개수와 타입이 같습니다. 필수는 “완전히 동일”이 아니라 호환입니다.

시그널슬롯
QSlider::valueChanged(int)slot_valueChanged(int)
sig_textChanged(QString)slot_textChanged(QString)
  1. 슬롯 인자가 더 적어도 됩니다. 뒤쪽 값은 버려집니다.
  2. 슬롯 인자가 더 많으면 안 됩니다.
  3. 앞쪽부터 차례로 맞춥니다. 순서를 바꿔 주지 않습니다.
  4. 타입이 변환 가능하면 됩니다. int → double은 되고, QString → int는 컴파일 에러입니다.
void foo();              // valueChanged(int)와 연결 가능
void bar(int a, int b);  // valueChanged(int)와 연결 불가

시그널은 사실상 void입니다. 슬롯의 return을 보낸 쪽이 쓰기 어렵습니다. 값을 돌려받아야 하면 일반 함수가 낫습니다.

10. 인자가 전달되는 메커니즘

기본은 Qt::AutoConnection입니다. 슬라이더와 Widget이 같은 GUI 스레드이므로 Direct입니다. 이벤트 큐를 거치지 않고 일반 함수 호출처럼 넘어갑니다.

Direct (이 예제)

moc가 만든 시그널 함수는 인자 값이 아니라 주소를 void* 배열에 넣습니다.

void QSlider::valueChanged(int _t1)
{
    void *_a[] = {
        nullptr,  // [0] 반환값
        const_cast<void*>(reinterpret_cast<const void*>(&_t1))
    };
    QMetaObject::activate(this, &staticMetaObject, /*시그널 번호*/, _a);
}
(receiver->*slot)(*reinterpret_cast<int*>(argv[1]));
// 즉 this->slot_valueChanged(42);

valueChanged가 리턴하기 전에 슬롯이 끝납니다. 스택의 int 주소를 써도 안전합니다.

슬라이더 드래그 → valueChanged(42) 스택에 42 → argv[1] = &42 → slot_valueChanged(42) 같은 스택에서 즉시 emit sig_textChanged(str) → slot_textChanged(str) → valueChanged 리턴

Queued (다른 스레드)

다른 스레드면 스택 주소를 쓸 수 없습니다. Qt는 인자를 QMetaType으로 복사해 QMetaCallEvent에 넣고, 수신 스레드 이벤트 루프에 게시합니다.

DirectQueued
시점emit 도중에 슬롯 실행이벤트 루프가 나중에 실행
인자주소로 즉시 전달복사본
조건같은 스레드수신 쪽에 이벤트 루프
이 예제사용 중사용하지 않음

Qt::BlockingQueuedConnection은 상대 슬롯이 끝날 때까지 기다립니다. UI 스레드와 섞으면 데드락이 나기 쉽습니다.

11. moc

moc는 Meta-Object Compiler입니다. Qt가 빌드 전에 돌리는 코드 생성기입니다. .o를 만들지 않고, 컴파일러가 이해할 C++를 만듭니다.

헤더에 Q_OBJECT가 있으면 moc가 클래스 이름, 시그널/슬롯 목록, 시그널 함수 본문, qt_static_metacall을 담은 moc_widget.cpp를 만듭니다.

#define signals public
#define slots           /* 빈 매크로 */
#define emit            /* 빈 매크로 */

컴파일러에게 시그널은 public 멤버 함수입니다. moc만 signals: 블록을 보고 시그널로 등록합니다.

widget.h -- moc --> moc_widget.cpp widget.ui -- uic --> ui_widget.h (UI Compiler, moc와 다름)

12. 컴파일러와 moc, 목적 파일과 실행 파일

12.1 moc의 입력은 보통 .h

일반 컴파일러: widget.h + widget.cpp → widget.o moc: widget.h (Q_OBJECT) → moc_widget.cpp widget.h ── moc ──→ moc_widget.cpp ── 컴파일러 ──→ moc_widget.o ─┐ │ ├─ 링크 → 실행 파일 widget.cpp ────────────────────── 컴파일러 ──→ widget.o ────────┘

moc는 보통 widget.cpp를 읽지 않습니다. 시그널/슬롯이 헤더 선언에 있기 때문입니다.

12.2 “기계어”가 들어간 말

기계어는 CPU가 읽는 명령 형식입니다. .o와 실행 파일은 그 명령을 담는 상자가 다릅니다. 기계어 = 실행 파일이 아닙니다.

말실제 의미
기계어CPU가 이해하는 명령 비트열
어셈블리어그 기계어의 텍스트 표기 (mov rax, 1)
바이너리텍스트가 아닌 바이트 데이터. .o·실행 파일·이미지가 해당될 수 있음
네이티브 코드그 컴퓨터 CPU용 기계어. Qt/C++ 결과물
바이트코드JVM 등 가상머신용. CPU 기계어 아님
목적 파일 (.o)한 .cpp의 미완성 조각. 기계어 + 심볼 + 재배치
실행 파일.o들과 라이브러리를 이은 완성본
소스 코드 widget.cpp 사람이 쓴 텍스트 ↓ 컴파일 목적 파일 widget.o 기계어 + 아직 구멍 있는 심볼 ↓ 링크 실행 파일 app/MacOS/... 합쳐진 기계어 + 라이브러리 정보 ↓ 실행 CPU 그 기계어 명령을 수행

.o에도 실행 파일에도 기계어가 있습니다. 차이점은 완성도입니다.

12.3 .o와 실행 파일

widget.o는 함수를 CPU 명령으로 바꾸지만, QString::arg 같은 Qt 함수 주소는 아직 모릅니다.

widget.o (macOS: Mach-O relocatable object) ├─ 헤더 / __TEXT(기계어) / __DATA ├─ 심볼 테이블 제공: Widget::slot_valueChanged / 필요: QString::arg └─ 재배치 정보 “이 위치의 주소는 나중에 고쳐 써라”

Linux는 ELF .o, Windows는 COFF .obj입니다. 혼자 실행이 안 되는 이유: main이 없을 수 있고, 외부 주소가 비어 있습니다.

링커가 widget.o + moc_widget.o + main.o + Qt 라이브러리를 이어 실행 파일을 만듭니다.

P01_SignalSlot.app/ └─ Contents/ ├─ MacOS/P01_SignalSlot ← 실제 실행 파일 (Mach-O) ├─ Frameworks/ ← Qt 등 .dylib └─ Info.plist

실행 파일의 __TEXT가 CPU가 읽는 기계어입니다. .o의 __TEXT도 기계어지만 주소가 아직 임시입니다.

13. 콜백과 비교, 적용 범위

시그널/슬롯은 콜백의 특수 형태입니다. “함수 주소를 저장해 두고 나중에 호출한다”는 점은 같고, Qt는 연결 목록·수명·스레드·타입 정보를 붙입니다.

일반 콜백Qt 시그널/슬롯
결합호출자가 대상을 앎보낸 쪽은 받는 쪽을 몰라도 됨
개수1개이거나 리스트를 직접 관리connect로 N:M
끊기직접 제거, 수명 실수 잦음QObject 파괴 시 연결도 정리
스레드직접 동기화/큐잉Queued가 값을 복사해 전달
필요 조건함수만 있으면 됨시그널을 내려면 QObject + moc

장점: 느슨한 결합, 한 시그널에 여러 슬롯, 객체 파괴 시 연결 정리, 스레드 간 복사 전달, UI 비동기 사건에 적합.

단점: 직접 호출보다 느림, 디버그 스택이 간접적, moc/이벤트 루프 의존, 반환값이 약함, Direct 재진입, 원격은 기본 기능 아님.

콜백이 나은 경우: 짧은 수명, 동기 결과, 핫패스, QObject가 필요 없는 순수 C++.

스레드

같은 프로세스의 다른 스레드까지 Qt가 지원합니다. Auto면 같은 스레드는 Direct, 다른 스레드는 Queued입니다.

  • 받는 쪽이 QObject이고 그 스레드에 이벤트 루프가 있어야 합니다.
  • Queued면 인자 복사가 가능해야 합니다. int, QString은 됩니다.
  • 다른 스레드 객체를 가리키는 포인터를 인자로 넘기는 것은 위험합니다.

한계는 프로세스 안, 이벤트 루프가 있는 QObject 사이입니다.

원격

connect 한 줄이 소켓 너머로 전달되지는 않습니다.

범위Qt가 해 주는가
같은 스레드 / 다른 객체됨
다른 스레드, 같은 프로세스됨 (Queued)
다른 프로세스 / 네트워크기본 connect로는 안 됨. D-Bus, QtRO, 소켓 등

원격에는 지연, 유실, 상대 종료처럼 로컬에 없던 문제가 생깁니다. 직렬화 + 전송 + 반대편에서 다시 emit이 필요합니다.

1. 함수 포인터/람다 같은 스레드, 직접 호출 2. Qt Direct 같은 스레드, 연결 목록 + 수명 3. Qt Queued 스레드 경계, 값 복사 + 이벤트 루프 4. 프로세스 버스 D-Bus, QtRO, IPC 5. 네트워크 Pub-Sub MQTT, gRPC stream 등

1–3은 Qt connect가 담당합니다. 잘 맞는 곳: UI 입력, 비동기 I/O, 상태 변경 알림. 안 맞는 곳: 핫패스, 반환값이 필요한 API, 인터럽트, 원격 RPC.

14. Qt가 시그널/슬롯을 구현한 방식

시그널/슬롯은 언어 기능이 아닙니다. 연결 목록 + moc 생성 코드 + QMetaObject::activate로 구현된 옵저버입니다.

[선언] Q_OBJECT, signals, slots ← 매크로 + moc가 읽는 표시 [생성] moc_widget.cpp ← 메타 테이블, 시그널 함수 [연결] QObject::connect ← Connection 노드를 두 리스트에 삽입 [방출] emit → 시그널 함수 → activate [전달] Direct / Queued [정리] QObject 소멸 ← 양쪽 리스트에서 Connection 제거
구성역할
QMetaObject클래스별 시그널/슬롯 목록
QObjectPrivate::Connection“이 시그널 → 저 슬롯” 한 줄
QSlotObjectBase새 문법용 호출 래퍼

14.1 moc가 만드는 것

클래스당 staticMetaObject가 하나 있습니다. 인스턴스가 아니라 타입이 목록을 가집니다.

Widget::staticMetaObject superdata → QWidget → … → QObject stringdata → "sig_textChanged", "slot_valueChanged", ... static_metacall → Widget::qt_static_metacall
void Widget::sig_textChanged(QString _t1)
{
    void *_a[] = { nullptr, const_cast<void*>(reinterpret_cast<const void*>(&_t1)) };
    QMetaObject::activate(this, &staticMetaObject, 0, _a);
}

새 문법은 멤버 함수 포인터를 IndexOfMethod로 넘겨 시그널 번호를 얻습니다. 문자열이 아닙니다.

14.2 Connection과 두 리스트

Connection ├─ sender / receiver / signal_index / connectionType ├─ slotObj (새 문법) 또는 qt_static_metacall 인덱스 (옛 문법) ├─ nextConnectionList 같은 시그널의 다음 슬롯 └─ next / prev 수신자가 받는 연결들 (소멸 시 정리) 보내는 쪽 (hSlider) signalVector[valueChanged] → Connection → ... 받는 쪽 (Widget) senders ↔ Connection ↔ Connection

양방향이라 어느 쪽이 먼저 파괴돼도 죽은 슬롯을 호출하지 않습니다.

14.3 connect와 activate

템플릿 connect가 컴파일 타임에 Q_OBJECT, 인자 개수·타입을 검사하고 QSlotObject를 만듭니다.

slotObj->call(receiver, argv);
// (static_cast<Widget*>(receiver)->*pmf)(*reinterpret_cast<int*>(argv[1]));

연결이 없으면 비트마스크만 보고 return 합니다. 연결 없는 emit은 거의 공짜입니다.

이 앱은 GUI 스레드 하나라 전부 Direct입니다. activate가 재귀로 한 번 더 들어갑니다.

ui->hSlider signalVector[valueChanged] Connection { receiver = Widget, slotObj = &Widget::slot_valueChanged } Widget signalVector[sig_textChanged] Connection { receiver = this, slotObj = &Widget::slot_textChanged } senders ↔ 위의 두 Connection

Qt 소스 본체: qtbase/src/corelib/kernel/qobject.cpp, qobject_p.h, 빌드 디렉터리의 moc_widget.cpp

15. 사용된 디자인 패턴

본체는 Observer입니다. 클래스가 그 이름을 쓰지는 않습니다.

GoF ObserverQt
Subject시그널을 가진 QObject (hSlider)
notify()emit → activate()
Observer슬롯 / 람다
attach / detachconnect / disconnect

update() 전용 인터페이스가 없고, 시그널이 객체마다 여러 개이며, 인자에 타입이 있습니다. 구현은 Observer, 사용감은 Pub-Sub에 가깝습니다.

  • Type Object / Flyweight — 클래스당 QMetaObject 하나
  • Command — QSlotObject, QMetaCallEvent. call()이 execute()
  • Adapter — 멤버 포인터·람다·moc 인덱스를 call(receiver, argv)로 통일
  • Strategy — Direct / Queued / BlockingQueued
  • Reactor — Queued의 이벤트 루프
  • Pimpl — QObjectPrivate
  • Code Generation — moc
connect(...) Adapter: QSlotObject 생성 Observer: Connection을 signalVector에 attach emit valueChanged(42) Type Object: 시그널 번호 Observer: activate()가 리스트 순회 Strategy: Auto → Direct Command: slotObj->call(...)

Mediator가 아닙니다. 발신 객체 안에 구독 목록이 있고, QApplication이 시그널을 중개하지 않습니다. Chain of Responsibility도 아닙니다. 슬롯 하나가 처리했다고 나머지를 막지 않습니다.

한 문장: Qt는 Observer를 moc 메타데이터와 Command 큐로 구현한 시스템입니다.

16. 한눈에 보는 전체 흐름

widget.h (Q_OBJECT, signals, slots) → moc → moc_widget.cpp widget.ui → uic → ui_widget.h 컴파일 → .o 여러 개 → 링크 → 실행 파일 실행 → QApplication::exec() 이벤트 루프 Widget 생성 QWidget(parent) → new Ui::Widget → setupUi(this) connect 두 줄 (예약만) 사용자 드래그 QSlider::valueChanged(int) Qt가 emit argv로 인자 주소 포장 activate → Direct → slot_valueChanged leText 갱신 emit sig_textChanged 우리가 emit activate → slot_textChanged leTextCopy 갱신
  1. 보내는 객체, 시그널 주소, 받는 객체(this), 슬롯 주소를 connect한다.
  2. connect는 호출이 아니라 예약이다.
  3. 라이브러리 시그널은 Qt가 emit하고, 직접 만든 시그널은 직접 emit한다.
  4. 인자는 같아도 되고, 슬롯이 더 적어도 된다. 더 많으면 안 된다.
  5. 같은 스레드면 즉시 호출, 다른 스레드면 복사 후 이벤트 루프.
  6. moc는 .h에서 .cpp를 만드는 코드 생성기다.
  7. private은 여전히 접근 제한이고, slots:는 옛 매크로용 표시에 가깝다.
